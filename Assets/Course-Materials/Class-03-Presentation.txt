SLIDE 2: What is a Prefab?
---------------------------
- Prefab = Reusable GameObject template
- Create once, use many times
- Changes to prefab affect all instances
- Saves time and ensures consistency
- Essential for game development workflow

SLIDE 3: Why Use Prefabs?
--------------------------
Benefits:
- Consistency: All instances are identical
- Efficiency: Update once, affects all
- Organization: Clean project structure
- Instantiation: Create objects via code
- Version control: Track changes easily

SLIDE 4: Creating a Prefab
---------------------------
Steps:
1. Create GameObject in scene
2. Configure it (components, materials, etc.)
3. Drag from Hierarchy to Project window
4. GameObject turns blue (prefab instance)
5. Original in scene is now linked to prefab

SLIDE 5: Prefab vs Instance
----------------------------
- Prefab: The template/master copy
- Instance: Copy of prefab in scene
- Blue name = Prefab instance
- Changes to instance = Override
- Can revert or apply overrides

SLIDE 6: Prefab Mode
---------------------
- Double-click prefab to enter Prefab Mode
- Edit prefab in isolation
- See only that prefab and its children
- Changes automatically apply to all instances
- Exit: Click arrow in Hierarchy or Scene

SLIDE 7: Overrides and Variants
--------------------------------
- Override: Change to prefab instance
- Bold property = Overridden value
- Right-click property: Revert or Apply
- Apply to Prefab: Updates master copy
- Revert: Returns to prefab values

SLIDE 8: Prefab Variants
-------------------------
- Variant: Prefab based on another prefab
- Inherits from base prefab
- Can add components or change values
- Base prefab changes affect variants
- Create: Right-click prefab > Create > Prefab Variant

SLIDE 9: Nested Prefabs
------------------------
- Prefab containing other prefabs
- Example: Car (prefab) with Wheels (prefabs)
- Maintains relationships
- Update child prefab = All parents update
- Powerful for complex objects

SLIDE 11: Prefab Workflow Best Practices
-----------------------------------------
- Create prefabs early in development
- Use descriptive names
- Organize in Prefabs folder
- Test prefab before using everywhere
- Document complex prefabs
- Keep prefabs simple when possible

SLIDE 12: Instantiation Basics
-------------------------------
- Instantiation = Creating object at runtime
- Done through code (C# scripts)
- Instantiate() function
- Specify: Prefab, Position, Rotation
- Returns reference to new instance

SLIDE 13: Transform Component Deep Dive
----------------------------------------
- Position: World or Local coordinates
- Rotation: Euler angles or Quaternions
- Scale: Local scale only
- Parent-child relationships:
  * Child inherits parent's transform
  * Local vs World space matters

SLIDE 14: Scaling Objects
--------------------------
- Scale values are multipliers
- 1 = Original size
- 2 = Double size
- 0.5 = Half size
- Non-uniform scaling: Different X, Y, Z
- Our bricks: Scale to desired size

SLIDE 15: Positioning in 3D Space
----------------------------------
- X axis: Left (-) to Right (+)
- Y axis: Down (-) to Up (+)
- Z axis: Back (-) to Forward (+)
- Origin (0,0,0): Center of world
- Grid helps with alignment

SLIDE 17: Prefab Icon Colors
-----------------------------
- Blue: Regular prefab instance
- Blue with +: Prefab with overrides
- White: Regular GameObject (not prefab)
- Gray: Disabled GameObject
- Helps identify object types at a glance

SLIDE 18: Breaking Prefab Connection
-------------------------------------
- Right-click instance > Unpack Prefab
- Completely: Removes all prefab links
- Completely (Root): Keeps nested prefabs
- Use when: Need unique one-off object
- Cannot undo unpacking!

SLIDE 19: Common Prefab Mistakes
---------------------------------
- Forgetting to apply changes
- Unpacking when not needed
- Not organizing prefabs in folders
- Making prefabs too complex
- Not testing before mass instantiation
