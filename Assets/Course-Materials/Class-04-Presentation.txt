---------------------

- Created by Microsoft
- Object-oriented programming (OOP)
- Type-safe and powerful
- Similar to Java and C++
- Great for beginners and professionals

SLIDE 4: Scripts in Unity
--------------------------
- Scripts are components
- Attach to GameObjects like any component
- Inherit from MonoBehaviour class
- Access to Unity's API
- .cs file extension
- Written in Visual Studio or VS Code

SLIDE 5: Creating Your First Script
------------------------------------
Steps:
1. Right-click in Project > Create > C# Script
2. Name it immediately (before pressing Enter!)
3. Double-click to open in code editor
4. Default template appears
5. Edit and save
6. Return to Unity (auto-compiles)

SLIDE 6: Script Anatomy
------------------------
```csharp
using UnityEngine;  // Import Unity functionality

public class MyScript : MonoBehaviour  // Class definition
{
    // Variables go here
    
    void Start()  // Called once at beginning
    {
        // Initialization code
    }
    
    void Update()  // Called every frame
    {
        // Game logic
    }
}
```

SLIDE 7: MonoBehaviour Lifecycle
---------------------------------
Key methods (in order):
1. Awake() - Called first, before Start
2. Start() - Called once, before first Update
3. Update() - Called every frame
4. FixedUpdate() - Called fixed timestep (physics)
5. LateUpdate() - Called after all Updates
6. OnDestroy() - Called when object destroyed

SLIDE 8: Awake vs Start
------------------------
Awake():
- Called first, even if script disabled
- Initialize references
- Set up object state

Start():
- Called after all Awakes
- Initialize after other objects ready
- Can access other objects safely

SLIDE 9: Update Method
-----------------------
- Called every frame
- Frame rate varies (30-120+ fps)
- Use for: Input, movement, timers
- Time.deltaTime: Time since last frame
- Keep Update() efficient!

SLIDE 10: Variables in C#
--------------------------
- Variable: Named storage for data
- Must declare type
- Syntax: type name = value;

Examples:
```csharp
int score = 0;           // Whole number
float speed = 5.5f;      // Decimal number
string name = "Player";  // Text
bool isAlive = true;     // True/False
```

SLIDE 11: Common Data Types
----------------------------
- int: Whole numbers (-2, -1, 0, 1, 2...)
- float: Decimals (3.14f, -0.5f, 100.0f)
- bool: True or False
- string: Text ("Hello", "Game Over")
- Vector3: 3D position (x, y, z)
- GameObject: Reference to object
- Transform: Position, rotation, scale

SLIDE 12: Public vs Private Variables
--------------------------------------
Public:
- Visible in Inspector
- Other scripts can access
- Use for: Settings, references

Private:
- Hidden from Inspector
- Only this script can access
- Use for: Internal calculations

```csharp
public float speed = 5f;    // Shows in Inspector
private int health = 100;   // Hidden
```

SLIDE 13: SerializeField Attribute
-----------------------------------
- Private but visible in Inspector
- Best of both worlds
- Syntax: [SerializeField] private type name;

```csharp
[SerializeField] private float jumpForce = 10f;
```

Benefits:
- Encapsulation (private)
- Inspector editing (public-like)

SLIDE 14: Debug.Log()
----------------------
- Print messages to Console
- Essential for testing/debugging
- Shows values of variables
- Tracks code execution

```csharp
Debug.Log("Hello World!");
Debug.Log("Score: " + score);
Debug.Log($"Position: {transform.position}");
```

SLIDE 15: Accessing Components
-------------------------------
- GetComponent<Type>(): Get component on same GameObject
- Common pattern:

```csharp
private Rigidbody rb;

void Awake()
{
    rb = GetComponent<Rigidbody>();
}
```

SLIDE 16: Transform Component
------------------------------
- Every GameObject has transform
- Access via: transform (lowercase)

```csharp
// Position
transform.position = new Vector3(0, 5, 0);

// Rotation
transform.rotation = Quaternion.identity;

// Scale
transform.localScale = new Vector3(2, 2, 2);
```

SLIDE 17: Comments in Code
---------------------------
- Comments: Notes for humans, ignored by computer
- Single line: // Comment
- Multi-line: /* Comment */
- Use for: Explanations, TODOs, documentation

```csharp
// This is a single line comment

/* This is a
   multi-line
   comment */
```

SLIDE 19: Common Scripting Errors
----------------------------------
- Missing semicolon ;
- Mismatched brackets { }
- Wrong capitalization (case-sensitive)
- Forgetting to save script
- Script name doesn't match class name
- Syntax errors prevent compilation

SLIDE 20: Reading Error Messages
---------------------------------
- Console shows errors in red
- Double-click error to jump to line
- Error format: File(Line,Column): Error message
- Fix errors from top to bottom
- One error can cause multiple messages

SLIDE 21: Best Coding Practices
--------------------------------

- Comment complex code
- Keep methods short and focused
- Consistent indentation
- Save frequently
- Test often
