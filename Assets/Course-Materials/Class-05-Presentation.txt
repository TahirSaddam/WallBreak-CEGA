SLIDE 2: What is Physics in Games?
-----------------------------------
- Simulation of real-world physics
- Gravity, collisions, forces
- Makes games feel realistic
- Unity has built-in physics engine
- 3D Physics: PhysX engine
- 2D Physics: Box2D engine

SLIDE 3: The Rigidbody Component
---------------------------------
- Enables physics simulation
- Makes object affected by gravity
- Responds to forces and collisions
- Required for realistic movement
- Add via: Add Component > Physics > Rigidbody

SLIDE 4: Rigidbody Properties - Mass
-------------------------------------
- Mass: How heavy the object is (kg)
- Default: 1 kg
- Affects: Collision response, force needed
- Heavier objects: Harder to move, more impact
- Lighter objects: Easier to move, less impact
- Our bricks: Vary mass for difficulty

SLIDE 5: Rigidbody Properties - Drag
-------------------------------------
- Drag: Air resistance (linear movement)
- Default: 0 (no air resistance)
- Higher values: Slows down faster
- Like moving through water vs air
- Use for: Projectiles, falling objects

Angular Drag:
- Resistance to rotation
- Slows down spinning

SLIDE 6: Rigidbody Properties - Gravity
----------------------------------------
- Use Gravity: Enable/disable gravity
- Checked: Object falls down
- Unchecked: Floats in place
- Gravity scale: Adjust fall speed
- Default gravity: -9.81 m/s² (Y axis)

SLIDE 7: Kinematic vs Dynamic
------------------------------
Is Kinematic (unchecked) - Dynamic:
- Affected by forces and gravity
- Collides with everything
- Physics engine controls movement
- Use for: Falling objects, projectiles

Is Kinematic (checked) - Kinematic:
- NOT affected by forces/gravity
- Can move via Transform
- Still detects collisions
- Use for: Moving platforms, doors

SLIDE 8: Constraints
--------------------
- Lock position or rotation on axes
- Freeze Position: X, Y, Z
- Freeze Rotation: X, Y, Z
- Prevents unwanted movement
- Example: Platform game character
  * Freeze Rotation Z (no tipping over)

SLIDE 9: Collision Detection
-----------------------------
Modes:
- Discrete: Fast, may miss collisions
- Continuous: Slower, catches fast objects
- Continuous Dynamic: Most accurate
- Continuous Speculative: Good balance

Use Continuous for:
- Fast-moving objects
- Small objects
- Critical collisions

SLIDE 10: Interpolation
------------------------
- Smooths physics movement
- Fixes jittery motion
- None: No smoothing (default)
- Interpolate: Based on previous frame
- Extrapolate: Based on predicted next frame
- Use for: Camera-followed objects

SLIDE 11: Physics Simulation
-----------------------------
- Runs at fixed timestep (default: 50 fps)
- Independent of frame rate
- FixedUpdate() syncs with physics
- Edit > Project Settings > Time
- Fixed Timestep: 0.02 (50 fps)

SLIDE 12: When to Use Rigidbody
--------------------------------
Use Rigidbody when:
- Object needs to fall
- Object responds to forces
- Object collides dynamically
- Realistic physics needed

Don't use when:
- Static objects (walls, ground)
- UI elements
- Simple transform movement sufficient

SLIDE 13: Rigidbody and Performance
------------------------------------
- Physics calculations are expensive
- More Rigidbodies = Lower performance
- Optimize:
  * Use kinematic when possible
  * Put sleeping objects to sleep
  * Simplify collision shapes
  * Reduce physics timestep if needed

SLIDE 14: Sleep Mode
---------------------
- Rigidbody "sleeps" when stationary
- Saves CPU cycles
- Wakes up when:
  * Hit by another object
  * Force applied
  * Moved via script
- Sleeping Mode setting: Auto, Always Awake, Never Sleep

SLIDE 15: Applying Forces
--------------------------
- AddForce(): Apply force to Rigidbody
- Must call in FixedUpdate() or event
- Force modes:
  * Force: Continuous force
  * Impulse: Instant force (hit, jump)
  * Acceleration: Ignores mass
  * VelocityChange: Instant velocity

```csharp
rb.AddForce(Vector3.up * 10f, ForceMode.Impulse);
```

SLIDE 16: Velocity
-------------------
- Velocity: Speed and direction
- Direct access: rb.velocity
- Set directly or use AddForce()

```csharp
// Get velocity
Vector3 currentVel = rb.velocity;

// Set velocity
rb.velocity = new Vector3(5, 0, 0);

// Modify velocity
rb.velocity += Vector3.up * 5f;
```

SLIDE 17: Our Brick Physics Setup
----------------------------------
Brick Rigidbody settings:
- Mass: Variable (30-400 based on level)
- Drag: 0 (no air resistance)
- Angular Drag: 0.05 (slight rotation damping)
- Use Gravity: Yes
- Is Kinematic: Yes (initially)
  * Becomes dynamic when hit
- Collision Detection: Continuous

SLIDE 18: Kinematic to Dynamic Transition
------------------------------------------
- Start as kinematic (wall stable)
- Switch to dynamic when hit
- Code:

```csharp
void DetachBrick()
{
    rb.isKinematic = false;  // Enable physics
    // Now affected by gravity and forces
}
```

SLIDE 21: Common Physics Issues
--------------------------------
- Object falls through floor: Collision detection
- Object moves too fast: Increase drag
- Object doesn't fall: Gravity disabled or kinematic
- Jittery movement: Use interpolation
- Object flies away: Too much force

SLIDE 22: Physics Best Practices
---------------------------------
- Use appropriate mass values
- Don't move Rigidbody via Transform
- Use ForceMode.Impulse for instant forces
- Keep physics objects simple
- Test with different mass values
- Use layers for selective collision
